# catalog-series-movies
# Практическая работа. Трансформация бизнес-параметров предметной области в спецификацию требований (SRS) информационной системы «Каталог сериалов и фильмов» (аналог MyShows)

**Цель работы:** начало анализа предметной области для курсовой, выявление всех типов требований и ограничений.

В рамках курсовой работы проектируется и реализуется информационная система — онлайн-каталог сериалов и фильмов с функциями отслеживания просмотренного. Система является аналогом сервиса MyShows и предназначена для пользователей, которые хотят вести учёт того, что они смотрят, ставить оценки, писать рецензии и получать персональные рекомендации.

На этапе предпроектного обследования заказчик предоставил сведения: «Сервис предназначен для отслеживания просмотренного, каталог содержит 50 000 сериалов и фильмов, 50 000 пользователей. Пользователи могут отмечать просмотренное, ставить оценки, писать рецензии, получать рекомендации. При сбое теряется прогресс просмотра».

- Для математика или организатора эти сведения представляют собой коммерческие параметры.
- Для инженера-программиста (SWEBOK) — это входные данные, под которые нужно спроектировать гибкое ПО.

Если вы жёстко зашьёте в код параметры на 50 000 тайтлов и 50 000 пользователей, программа будет одноразовой и бесполезной.

**Наша главная задача:** перевести параметры бизнес-контекста в спецификацию функциональных требований (FR), нефункциональных требований (NFR) и системных ограничений (Constraints).

## Шаг 2. Спецификация функциональных требований (FR)

| ID     | Название                        | Формулировка требования                                                                                                      |
| ------ | ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| FR-01  | Ведение каталога                | Система должна хранить структурированные данные о 50 000+ сериалах и фильмах с полями: название, год, жанры, описание, постер, рейтинг. |
| FR-02  | Полнотекстовый поиск            | Система должна обеспечивать поиск по названию, описанию и ключевым словам с временем отклика не более 300 мс.                 |
| FR-03  | Фильтрация и сортировка         | Система должна позволять фильтровать каталог по жанру, году, рейтингу, типу (сериал/фильм) и сортировать по популярности.     |
| FR-04  | Карточка тайтла                 | Система должна отображать карточку тайтла с постером, описанием, актёрами, рейтингом, количеством оценок.                     |

## Шаг 3. Нефункциональные требования (NFR) на базе ISO 25010

Бизнес-контекст: «50 000 пользователей одновременно отмечают просмотренное в 21:00».

| Категория ISO 25010      | Контекст предметной области                              | Инженерная формулировка требования (NFR)                                                                                      |
| ------------------------ | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Performance Efficiency   | 50 000 пользователей одновременно в 21:00                | NFR-01: Пиковая нагрузка не менее 3000 RPS на эндпоинт отметки, Latency p95 ≤ 200 мс.                                          |
| Performance Efficiency   | Поиск по каталогу из 50 000 тайтлов                      | NFR-02: Время отклика поиска p95 ≤ 300 мс.                                                                                     |
| Performance Efficiency   | Формирование персональных рекомендаций                   | NFR-03: Эндпоинт рекомендаций отвечает ≤ 500 мс для p95.                                                                       |
| Reliability              | Сбой ведёт к потере прогресса просмотра                  | NFR-04: Исключить SPOF. Availability ядра отметок ≥ 99.9% (SLA).                                                               |
| Reliability              | Потеря данных о просмотрах недопустима                   | NFR-05: RPO ≤ 5 минут, RTO ≤ 30 минут.                                                                                        |
| Usability                | Пользователь отмечает просмотренное со смартфона         | NFR-06: Mobile-first, размер страницы тайтла ≤ 200 Кб (gzip/brotli).                                                          |
| Usability                | Доступность для людей с ОВЗ                              | NFR-07: Соответствие WCAG 2.1 уровня AA.                                                                                      |
| Security                 | Риск утечки персональных данных                          | NFR-08: OAuth 2.0/JWT, шифрование AES-256 при хранении и передаче.                                                            |
| Security                 | Защита от ботов и парсинга                               | NFR-09: Rate Limiting ≤ 100 запросов/мин с одного IP для неавторизованных.                                                     |
| Maintainability          | Смена внешних источников метаданных                      | NFR-10: Модуль импорта изолирован через «Адаптер», покрытие unit-тестами ≥ 80%.                                                |
| Maintainability          | Быстрое развёртывание обновлений                         | NFR-11: CI/CD с автотестами и откатом ≤ 10 минут.                                                                             |
| Compatibility            | Разные браузеры                                          | NFR-12: Поддержка последних двух версий Chrome, Firefox, Safari, Edge.                                                        |
| Compatibility            | Интеграция с TMDb/OMDb                                   | NFR-13: REST API с версионированием и OpenAPI-спецификацией.                                                                   |
| Scalability              | Рост числа пользователей и тайтлов                       | NFR-14: Горизонтальное масштабирование транзакционного и аналитического контуров независимо.                                  |
| Quality (ML)             | Качество рекомендаций влияет на удержание                | NFR-15: precision@10 ≥ 0.6 на валидационной выборке.                                                                          |
| Quality (ML)             | Модели обновляются без деградации                        | NFR-16: Ежедневное переобучение, мониторинг дрейфа данных с оповещением при отклонении > 10%.                                 |



## Шаг 4. Системные ограничения и допущения (Constraints)

| ID           | Название                          | Описание                                                                                                       |
| ------------ | --------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Constraint-01 | Единая модель данных             | Основное хранилище транзакционных данных — PostgreSQL с поддержкой ACID.                                       |
| Constraint-02 | Формат метаданных                | Импорт только из открытых источников (TMDb, OMDb) через REST API.                                              |
| Constraint-03 | Аутентификация                   | Поддерживаются только email/пароль и OAuth 2.0 (Google, VK). 2FA не реализуется.                               |
| Constraint-04 | Язык интерфейса                  | Интерфейс только на русском и английском. Мультиязычный контент не переводится.                                |
| Constraint-05 | Типы контента                    | Только фильмы и сериалы. Книги, игры, комиксы не добавляются.                                                  |
| Constraint-06 | Рекомендации                     | Только на явных и неявных действиях внутри системы. Анализ соцсетей не выполняется.                            |
| Constraint-07 | Платежи                          | Платные подписки и встроенные покупки отсутствуют. Сервис бесплатный.                                          |
| Constraint-08 | Хранение истории                 | История просмотров хранится не менее 5 лет с момента последней активности.                                     |
| Constraint-09 | ML-стек                          | Python, scikit-learn, implicit. GPU-ускорение не требуется.                                                    |
| Constraint-10 | Интеграции                       | Нет интеграций с торрент-трекерами и стриминговыми платформами для просмотра.                                  |
